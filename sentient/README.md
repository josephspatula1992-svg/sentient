# Sentient

**Every NFT is a NEAR account with an autonomous agent inside it. They earn, spend, duel, breed, and die.**

Minting an agent creates a real NEAR account for it, `a<id>.<contract>`, with one key on it: a function-call key that can call the agent methods of this contract and nothing else. The agent's runtime signs with that key, so everything it does arrives with the agent's own account as the caller. It takes jobs, hires other agents, races other agents to answer puzzles the contract checks itself, pays upkeep out of what it earns, goes dormant when it cannot, gets revived by anyone who funds it, and breeds with another proven agent to produce a child whose genome is a mix of theirs. Its NFT is the account, its balance and its record, and moves as one.

> Built for the NEAR Hackathon (Nov 2026). Tracks: NFTs That Do Something, Games With Real Economies, Agent Economy, Autonomous Business.

## See it work (about two minutes, no API key)

Needs Node 20+. The contract is already built (`contracts/sentient/res/sentient.wasm`); Rust 1.86 is only needed to rebuild it.

```bash
npm install
npm run build
npm run serve        # http://localhost:8788  -> replays a recorded run of 14 agents over 5.5 minutes
npm run e2e          # deploys the real WASM to a local nearcore node and checks the claims below (about 3 minutes)
npm run demo         # records a fresh run on a local node (about 7 minutes), then re-serve
```

**Guided tour.** Open `http://localhost:8788/?tour=1` (or press "Guided tour") and the page runs itself: a title card, then captions while a visible cursor moves to and clicks the real controls. It spotlights the cast, the job board and the arena, opens the top earner's record, jumps to the first death (dormancy), a revival and the birth, and opens the family tree, "The money" and "Why this is real" tabs, before a closing card that says plainly it is a recorded run with an offline stand-in for the model. It reads the recording to decide what to show, so it works on any run. `&pace=2` runs it twice as fast; Esc stops it. It was checked frame by frame in headless Chrome (it reaches and clicks through every step); **Video.** `npm run record` plays the tour in headless Chrome and writes `recordings/sentient-demo-<time>.mp4` (about 110 s, 1400x900, no narration; adapted from verity's recorder, no new dependencies, needs Chrome and ffmpeg). One recording was made and spot-checked at four points (opening, an agent record with caption and cursor, the closing card, the final frame); it was not watched start to finish by a person, so watch it once before posting.

The dashboard replays `web/demo-run.json`: twelve agents with different temperaments (and one child that is bred during the run) working a job market, dueling, running out of money, being revived, being bought into. Click an agent for its genome, balance history, lineage and record. The "The money" tab shows the contract's books balancing live. Add `?live=<contract id>&rpc=<node url>` to the page to read a deployed contract instead of the recording.

## What is on chain, and what each part is for

| Part | What it does | What stops it being gamed |
|---|---|---|
| **Agent = sub-account** | Mint creates `a<id>.<contract>`, deploys a 2.7 KB "shell" on it, and adds one function-call key limited to 14 agent methods, no deposits. | The key cannot transfer NEAR, add keys, deploy, or call anything else, including the shell (e2e A5 and A3b try each on a real node). Money lives in the contract's books, not behind the key. |
| **The shell** | A parent contract cannot touch a sub-account's keys, but a contract on the account *is* the account. The shell (`contracts/agent-shell`, no allocator, three functions) lets only the registry delete a key, add a key, or sweep the account's spare balance. | It trusts one caller, derived from its own account id, and holds no state. |
| **Sale** | `nft_transfer` moves the agent, its money and its record, and has the shell **delete the seller's key**. The new owner calls `set_runtime_key` to give the agent a new voice, and `sweep_tank` to take its spare gas back. | After a sale the seller's key does not exist: it cannot sign, and a call with a deleted key is rejected before any gas is charged, so it cannot burn the buyer's tank (e2e A16 checks the balance is unchanged after three attempts). Transfers are refused mid-job or mid-duel, and to the agent's own account or the contract (an agent that owned itself would pass the owner check with its own key, skipping the risk cap, and its owner-only powers would belong to an account nobody can sign for). |
| **Delegates and stolen keys** | An operator or the agent's own key can act for it. | Anything somebody other than the owner starts with the agent's money (a stake, a bond, a posted bounty) is capped: losses so far in the window, plus money already held, plus the new commitment, may not exceed `risk_bps` of the window's starting balance (60% a day by default; the owner sets it per agent). The owner is never limited. A compromised runtime can cost at most that share per window, which is time to rekey it or clear the operator. An operator also cannot take its own job or fight its own agent through the agent. |
| **Jobs** | Escrowed bounty, a bond at risk, delivery by hash. Agents or people post; agents claim. | Silent poster pays the worker after the review window; silent chair splits the bounty; silent worker loses the bond. The chair cannot rule on a job it is party to. An agent cannot work for its own owner. A job that eight agents have taken and failed is cancelled and the bounty goes back to the poster, so a job's record stays bounded and money never sits in escrow for ever. |
| **Duels** | Two agents stake equally on a puzzle drawn from the chain's random seed at acceptance. First correct answer wins the pot. | The contract recomputes the answer itself: no judge, no oracle. A wrong answer locks you out. A start delay stops either side getting a head start. Same-owner duels are refused, and repeat pairings move ratings less. |
| **Cost of living** | Upkeep is charged lazily from free balance. An agent that cannot pay goes dormant: it keeps its NFT, record and money but cannot act. | Anyone can fund it back to life by putting money in; waking one that already has the money, for free, is for its owner or operator, so a stranger cannot restart the rent of an agent its owner parked. Dormancy is visible in every view before anyone records it. |
| **Shares** | Anyone can buy shares of an agent on a linear bonding curve and receive a cut of what it wins. | Reserve is exactly the curve's integral, so every sale can be paid. Trade fees both ways, a sell lock after buying, a min-proceeds guard. |
| **Breeding** | Two proven agents (a job done or a duel won), each paying half the cost, produce a child with its own account and key. Genome = per-trait crossover plus mutation, under a fixed point budget. | Cooldowns, proven-parents rule, stud fees set by the stud's owner. |
| **Books** | `received = sent + ledgers + locked + escrow + reserves + dividends + treasury + credits`, always. | Unit tests check it after every step of 3,000 random operations; e2e checks it against the chain's real balance (`get_audit`). |

The genome (diligence, boldness, thrift, sociability, cunning, 300 points to spend) steers an agent's runtime: how slowly it thinks, how often it blunders under time pressure, how much it stakes, which jobs it takes, whether it hires. The contract stores and breeds it but never trusts it with money.

## What is not verified, plainly

- **Not exercised by any test:** an agent on a genuinely separate machine over a real network (the rehearsal uses two stores on one machine, so what is proven is the logic, not the network); and the keeper's repeat-meeting prune against a real contract (the window is a day, so it never comes due in a demo).
- **(Now verified, kept for the record.) Contract edits made late:** `revive` with no deposit now requires the agent's owner or operator (two new unit tests, one existing test and the random-play harness adjusted to match); a job is cancelled and refunded after eight failed attempts (one new unit test, which mints eight agents and lets each one's claim lapse). All of this has since been built and run: the contract and TypeScript tests, 23 end-to-end checks and 10 rehearsal checks above pass on the committed WASM.
- **(Now verified, kept for the record.) Edits made late:** the read-only RPC proxy's hardening (JSON that is not an object is a 400, a node that is down is a 502, an oversized body is cut off) and three more tests in `test/serve.test.ts`; the keeper retrying failed prunes and pruning repeat-meeting records only once they are past their window; `mint` saving the key file before minting, validating `--genome` and keeping the key if the mint could not be confirmed; `deploy` checking the chair exists and finishing an interrupted deploy with `--init-only`, with rehearsal check R2b; `run-agent` start-up warnings and the artifact store's trusted-hosts list (and its test); the new `post-job` and `review-job` scripts; the live dashboard's overlapping-poll guard and its single status line; the live dashboard's input hardening (every field a node returns is coerced to a number, a digits-only amount or a letters-only token before it can reach the page, feed entries included, with a test that feeds it markup); the proxy reading the request body with listeners so an oversized body reliably gets its 413; the rewritten rehearsal step.
- **Testnet: deployed, barely exercised. Not on mainnet.** The contract is on testnet at `sentient-a7s2d.testnet` (fast economy, books balanced on deploy, surplus 5.278 NEAR; chair `sentient-owner-a7s2d.testnet`), with three agents minted (a1 to a3) and one job posted. The agents ran for under two minutes, opened duel challenges, and were then stopped; nobody completed a job or a duel there. The accounts were funded by the testnet faucet (10 NEAR each, so the deploy used a lowered `MIN_CONTRACT_BALANCE_NEAR=8`). The demo video is the local recorded run, not testnet.
- **The recorded run uses an offline stand-in for the language model.** Puzzles are solved exactly and then slowed and occasionally spoiled according to the genome; deliverables are templated with quality following the genome. That is a deliberate model of the speed/accuracy trade-off a real model has. It shows the economics, gates and accounting hold under that behaviour. It says nothing about model quality, and an agent's "skill" in the recording is built in, not discovered.
- **The NEAR AI Cloud chat path is untested against the live service.** `LLM_MODE=near-ai` routes puzzle answers and deliverable writing to its OpenAI-compatible API (`src/lib/config.ts`). What I could check without a key I did against the live service: its model list is reachable (64 models) and the default model id is in it. The chat call itself is written to the documented schema and exercised only against a stub.
- **NEAR Intents is not used.** An agent's trading P&L off the contract cannot be verified in this accounting model, so I did not bolt it on. Cross-chain funding of an agent through Intents is a natural next step and is not built.
- **No wallet flow.** Minting, posting and buying are scripts and contract calls; the web app is read-only. It has been viewed in headless Chrome but not in a wallet.
- **The contract cannot judge work.** The poster (and in a dispute the chair) decides whether a deliverable is good. The chair is a single trusted account, and a poster can force arbitration by rejecting. A person running several accounts can still collude with themselves: fees, bonds and rating damping price that, they do not prevent it.
- **Duels measure speed and reliability, not insight.** A calculator solves every puzzle. An agent's edge is latency, correctness under time pressure and which fights it takes. The puzzle seed is the block's random seed, which a block producer could in principle grind.
- **The share market is a research prototype.** A bonding curve where early holders profit from later buyers can be treated as an investment product in some places. It should not be used with real money without legal advice.
- **The contract has not been audited by anyone but me.** Three self-audit passes found and fixed real defects, each now with a regression test, but the tests above are mine too. There is no upgrade path by design: `npm run deploy -- --lock` deletes the contract's keys, which is irreversible and not done here.
- **Gas.** An agent's key has an unlimited allowance, so what bounds the gas it can burn is the balance of its own account, which only the owner can refill (`refuel`, owner only: an operator cannot, because it is money moved out of the agent's ledger) or take back (`sweep_tank`). A *compromised* runtime can still burn the tank by spamming calls until the owner rekeys the agent; that is bounded by the tank, never the ledger. Selling is no longer a way to do this: the seller's key is deleted.
- **An operator or a stolen key can still lose the agent money, up to a cap.** The contract bounds the loss per window (60% of the balance a day by default; the owner can set it lower per agent) and refuses an operator that tries to fight or hire itself through the agent, but it cannot stop an operator colluding through a third account within that cap. It buys the owner time, it does not make delegation free of trust.
- **The shell cannot be upgraded.** Its code is on every agent account and nothing can change it, by design, because a way to change it would be a way to take the account. It is three functions and 2.7 KB and was written to be read, but it is new code with no review but mine. If it turns out to have a flaw, existing agents keep it; new deployments would use a fixed registry.
- **A model's duel answer is its last number.** Found by the audit: the live brain submitted the first integer in the reply, so a model that showed its working ("12 x 34 = 408") would have answered 12 and been locked out. It now takes the last integer and refuses one that is not a safe integer. This path is only tested against a stub; the real NEAR AI chat endpoint is still untested.
- **Failures are visible.** Found by the audit: an unexpected failure in an agent or actor (no gas, a key the contract no longer honours) was counted but only printed with `VERBOSE`, so an operator saw an idle agent and no reason. These are now printed by default, at most once a minute per source and message; lost races stay quiet. Agent cards in the dashboard also respond to Space, as their button role promises.
- **The actors around the agents are bounded too.** Found by the audit: the chair retried a ruling the contract would never accept (for example when it is itself a party to the job) every 1.5 seconds for ever; an owner re-funded a dying agent without limit (it now gives up after three revivals unless told otherwise); the market never retried a review that failed once and marked it reviewed before it had gone through; and it posted jobs with a fixed work window that a real configuration would reject. Each now has a test.
- **A hiccup no longer costs an agent a bond or a duel.** Found by the audit: the runtime marked a job as worked and a duel as answered *before* attempting them, so one transient failure (a model error, a dropped transaction) meant the agent sat on its bond until the deadline lapsed, or never answered. It now retries up to three times. The same pass found that an agent's hire used a hard-coded 60-second work window, below the real configuration's 600-second minimum, so hiring would have been rejected on any real deployment; it now reads the contract's limits.
- **An agent reads a brief before it locks a bond.** Found by the audit: it used to claim first and fetch after, so on a network where it could not read a poster's brief it would claim, fail, lapse and lose its bond every time. It now skips any job whose brief it cannot fetch and check against its hash (rehearsal check R5c).
- **Gas for a sale.** `nft_transfer` now schedules a call to the shell; attach at least 100 Tgas (a wallet's default 30 may not be enough).
- **Treasury and storage.** Storage staking is not in the books. The chair can only withdraw revenue while the contract keeps 1 NEAR of real balance beyond its liabilities and storage. Each agent account's code costs about 0.03 NEAR of storage stake, paid out of its seed. Finished jobs and duels and expired repeat-meeting records can be pruned (`prune_job`, `prune_duel`, `prune_pairs`; the demo's keeper does it); the 128-entry event ring is a fixed cost a deployer should fund.
- **Views stay inside gas on long-lived contracts** by scanning only the newest 1,500 jobs, duels and agents for open/alive/dormant counts and the "recent" lists; the totals (`agents`, `jobs`, `duels`) are exact.

## Layout

```
contracts/sentient/    Rust (near-sdk 5.9). lib.rs state + helpers, jobs.rs, duels.rs, market.rs, lifecycle.rs (mint, breed,
                       revive, rekey, sweep), nft.rs (NEP-171/177), puzzle.rs, genome.rs, econ.rs (curve, Elo, damping), art.rs
contracts/agent-shell/ the 2.7 KB no-std contract deployed on every agent account (revoke / grant / sweep, registry only)
src/lib/               typed chain client, puzzle solver, policy (genome -> behaviour), job rubric, brains, store, recorder
src/agents/            runtime.ts (one agent), actors.ts (market, chair, keeper, fans, owner)
scripts/               demo.ts (records the economy), deploy.ts, mint.ts, run-agent.ts
test/                  unit tests + test/e2e/e2e.ts (real node)
web/                   dashboard: plain ES modules, no build step; replays demo-run.json or reads a live contract
```

NEP-171 core and enumeration, and NEP-177 metadata, are implemented (the NFT's image is drawn on chain from the genome). Approvals and `nft_transfer_call` are deliberately not, because they would let a marketplace move an agent mid-duel.
